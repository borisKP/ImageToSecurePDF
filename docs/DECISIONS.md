# 决策记录

固定日期：2026-11-21。按时间顺序记录已做出的关键决定，改天继续时不要无故推翻。

## D1：产品名 = ImageToSecurePDF

用户确认。仓库名、品牌、版本徽章统一使用此名；中文副标题保留「图片合集 → 加密 PDF」以免丢失原有语义。

## D2：共享引擎用 Go，不用 Python

用户从三个选项中明确选择「Go 双端（推荐）」。

理由：Go 引擎已解决加密包直读、目标体积二分压缩、有界并行、截断 JPEG 修复这些最难的部分；Python 方案会让 macOS 包变大、性能下降，且 RAR 仍依赖外部工具。

## D3：两个原生前端，不做单一 Qt 界面

macOS 沿用 Swift/AppKit，Windows 沿用 PySide6。

理由：保留两端原生体验和已有界面资产；B 的 v1 浏览器界面已验证用户不喜欢。

## D4：macOS 前端直接复用真机完整源码

第一版用 440 行 SwiftUI 草稿，用户反馈粗糙。已改为复用本机 `/Applications/图片合集转加密PDF.app` 对应的 2711 行 `macapp/App.swift` 源码，只改品牌、版本、helper。

后续所有 macOS UI 改动都基于这份完整源码，禁止重写简化版。草稿保留为 `macos/App.swift.swiftui-draft.bak` 作反面参考。

## D5：Windows 前端也应复用原 Studio 完整界面

当前 `windows/app.py` 是骨架，仅用于验证协议。正式开发应基于 `ImageToPDF_Studio/src/{app,i18n,theme}.py`，只替换转换调用。

## D6：默认页面模式 = fit

A 按 DPI 还原物理尺寸，B 用 96 dpi 的 fit 无白边。合并版默认保持 fit，把 DPI/纸张模式作为高级选项，避免老用户页面突然变大。

## D7：不保留 RC4-128

安全性低。第一版只实现 AES-256；AES-128 是否加入待定，但不能为了兼容牺牲默认安全。

## D8：密码不落盘

密码只在内存使用，不写日志、不写错误报告。错误报告只记录「是否设置密码」。这是从 B 继承的硬性规则。

## D9：多语言用 key/args

引擎只发语言无关的 `{key, args}`，界面查表渲染。切换语言时整段历史日志可重翻，避免英文界面出现中文。

## D10：第一版不上传二进制产物到 GitHub

App bundle、DMG/ZIP、测试 PDF/压缩包、截图不入库，通过脚本重新生成。仓库只保留源码、文档、配置和可复现的测试脚本。

## D11：仓库可见性 = public

两个原仓库均为 public + MIT，新仓库保持一致。
